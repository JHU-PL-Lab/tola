A _pre: / _post: column is ONE AGREEMENT at one point in the chain — _pre a requirement the next action depends on, _post a verdict on what the last one made — and its cell is that agreement's own outcome, so a column can be read down the rows and compared. A claim gets a column only where it can be decided: not where it is unimplemented, and not where the mechanism cannot carry it (an OCaml .a archive records no NEEDED, so the identity claims have no column on that side and do on Python's shared object). An =artifact column is not a stage and nothing runs there — it is what the action LEFT BEHIND, read off the inspection that step wrote (a library shows its soname tail and export count, a binding its module count). It turns red when a check that read it failed, so a finding names both the claim that broke and the artifact it was about.
