nodelayerwhat it is
system PMpmapt, brew, dnf — resolves and installs native packages
native packagepackagethe unit the system PM ships: payload plus metadata
native sourceartifactthe library's own repository at a ref — present when the world builds rather than fetches
headersartifactthe syntactic native surface a binding compiles against
native libraryartifactthe link-time and runtime carrier: exported symbols, identity, recorded dependencies
staged copyartifactthe install-prefix face of the same library — a second copy, which is why a claim can compare them
capability filepackagea .pc file, a CMake config, a *-config script: content inside the provider, owned by the package that ships it, recording how the artifacts beside it are built against. Not a bridge — a source of claims, and what a conf package's check reads
bridge packagepackagea separate package existing only for cooperation (opam's conf-*). Carries package IDENTITY and the depext mapping. THE SYMBOLIC BRIDGE
language PMpmopam, pip, cargo — solves constraints and installs
binding packagepackagethe unit the language PM ships, with its declared depends
binding sourceartifactthe binding's own repository — separate from the library's, and often at a different ref
stubartifactthe binding's shim to the library, where its mechanism has one: what records the symbols it requires of the library
language moduleartifactthe compiled language-side artifact the consumer links
user surfaceartifactthe names and types the binding offers its own users
consumer (artifact-linked)programevery input named by path — the language module and the native library. Says the CODE is right
consumer (package-linked)programnames only the binding package and lets the PM resolve the rest. Says the RECIPE is right — which is the half a build-tree probe cannot see
