# Diagram system

Canary generates Mermaid diagrams and an HTML viewer per run.
Backlog refs: #36 (summary node fidelity), #37 (HTML viewer).

---

## Overview

Every `canary action <project>` run writes:

```
_out/canary/projects/<project>/<variant>/
  result.mmd          ← schema-level overview diagram
  result.html         ← interactive HTML viewer (all views + log drawer)
  diagrams/
    source.mmd
    lib.mmd
    pack.mmd
    probes.mmd
    binding_ocaml.mmd
    binding_python.mmd
```

`_out/canary/index.html` is a top-level index across all runs (project × variant table with pass/fail status).

---

## result.mmd — overview

The overview uses `Canary.mermaid_of_action_rule_schema`, the schema-level
renderer in `canary.ml`. It shows:

- **Artifact pool nodes** (docs shape, orange) — one per artifact kind
  (Source, Lib, Binding OCaml/Python, App). Fetch steps embed their step
  ID in the artifact label (`lib [3]`); multiple fetch variants collapse
  into one node with combined IDs (`probe_lib [17][19][21]`).
- **Action nodes** — hexagons for transformations (build/install/pack),
  pills for probes and follow-up steps.
- **Follow-up steps** — `scan_source` and `*_summary` / `*_stub_summary`
  steps rendered as pill-shaped annotation nodes connected by dashed edges.
- **Step IDs** — stable 1-based indices (execution order) embedded in
  every node label for cross-reference with `actions.log`.
- **Status colours** — green (done), red (failed), grey-dashed (skipped),
  light grey (not-in-spec) when run with `--status`.
- **Edge colours** — match the status of the step the edge leads to.

## Per-view diagrams

Each view is generated by `mermaid_view` in `canary_action.ml`, which
calls the same schema renderer with two modes:

**Artifact views** (`lib`, `binding_ocaml`, `binding_python`): the full
schema graph with the focused artifact expanded into per-variant docs nodes.
For example, the lib view for `llvm/dev` shows:

```
lib (apt) [7]      ← from fetch_lib_apt
lib (build_tree)   ← from build_lib
lib (staged)       ← from install_lib
```

All other artifacts remain as single collapsed nodes. Steps not executed
in this variant appear as nospec (grey), providing context for what was
skipped.

**Non-artifact views** (`source`, `pack`, `probes`): the full schema graph
unchanged — same as the overview but with a `%% view: <name>` title. These
tabs are useful for reading step IDs in context (e.g., probes view shows
all probe results against the full build chain).

The focused artifact's variant nodes are computed from the actual probe
step tags: `probe_lib_apt` → variant `apt`; `probe_lib` (no suffix) →
default alias resolved by `_default_variant_alias` (build_tree if a build
step ran, else first PM type, else "fetch").

## result.html — interactive viewer

`canary_backend_html.ml` generates a self-contained HTML page per run:

- **View selector** tabs — Overview, Source, Lib, Pack, Probes,
  Binding (OCaml), Binding (Python). Switches the Mermaid block without
  page reload.
- **Mermaid render** — via mermaid.js v11 CDN. Syntax errors are caught
  and displayed inline.
- **Node click → log drawer** — each action node in the diagram carries a
  step tag; clicking opens a side panel that lazily fetches the step's
  `output_dir` files (probe.log, summary.json, etc.) via relative path.
- **Back link** — `← all runs` at the top links to `../../index.html`.

---

## index.html — top-level index

`_out/canary/index.html` is regenerated after every run and on
`canary index`. Lists all (project, variant) runs as a table with:
- project / variant / source kind (dev build vs stable fetch)
- overall status badge
- link to the run's `result.html`

## Still open

- **Version annotations** on artifact nodes — e.g. `lib (apt 19.1.7)`
  instead of `lib (apt)`. Requires querying installed package versions
  (opam info, dpkg-query, pip show) or reading from summary.json.
- **Expectation display** on probe nodes — the `Expect_compat_failure`
  rationale is currently only in the log drawer, not visible in the
  diagram node.
- **Bundled mermaid.js** — CDN is the current default; offline use
  requires an explicit `--bundle-mermaid` flag (not yet implemented).
